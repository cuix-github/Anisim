# 喷雾阶段 1–3：实现、2D 对照与验收边界

2026-10-23。本轮只做规格、实现核查与 2D 粒子实验。现有 40 秒海浪缓存、正式启动器和渲染预设没有改动。没有运行粗 3D、正式海浪或 Arnold。

**结论：新喷雾机制的局部数值验证通过，但默认 Python 与 Bifrost 的完整模拟一致性未通过，不能据此进入正式重跑。** 独立运行暴露了已有的相场定义差异；自适应联动测试另发现并修复了一个索引错误。不能把修正参数后的好看画面当作论文实现完整性的证明。

## 1. 这一轮实现了什么

`emit_model=2` 是显式启用的新路径，旧的 0/1 路径保留。每个合格界面源的期望事件数为 `lambda = rate * max(G - threshold, 0) * dt`，其中 G 为速度梯度的 Frobenius 范数，单位 1/s。采用随机取整产生事件数，因此 lambda 大于 1 时不再被单次出生概率截断；这不是 Poisson 过程。

每次事件生成 N 个分开的位置和速度样本，并立即赋予正半径。采用公开论文所述的 lognormal 类型分布；这里的具体采样和参数归一化是本项目明确写出的实现选择，不能称为作者未公开实现的复刻：

`r_i = R * N^(-1/3) * exp(sigma*Z_i - 1.5*sigma^2)`。

由于正态变量满足 `E[exp(3*sigma*Z)] = exp(4.5*sigma^2)`，未截断时 `E[sum(r_i^3)] = R^3`。所以增加 N 表示在相同**期望事件水量**下分得更细；增加 rate 表示发射更多事件。它不保证每个事件恰好守恒。半径截断、边界拒绝与预算截断之后，实际代表水量可能改变，记录中保留了原始与截断后的 `sum(r^3)`。

每步记录候选、事件、请求、实际出生、预算拒绝、几何拒绝、蒸发、回水与存活数量。全局活跃粒子上限和逐格上限都是计算预算，不伪装成物理发射率。出生位置不允许在固体内或越界，拒绝后不会挤在边界。

`droplet_model=2` 在预测的中点重新采样空气速度，使用指数阻力松弛，并限制子步长。原始逃逸 FLIP 粒子的分类与数值质量没有被重新定义；本轮没有实现把每个逃逸 FLIP 质量包守恒地碎裂成一群液滴。

详细参数、单位、数学和限制见 [实现规格](spray-events-2d.md)。源码入口为 [NumPy 采样器](../reference2d/spray_events.py)、[C++ 采样器](../nodes/src/PFFlipSprayEvents.h) 和 `step_3d` 的显式模式 2。

联动测试第一次失败不是视觉差异：C++ 拆分粒子后没有同步压缩用于下一阶段合并判断的液相比例数组，导致它与粒子索引错位。喷雾出生改变数组长度，间接改变了主体空气粒子的合并。现已使判定数组随粒子一起重排，并让新拆分的子粒子在本步保持精细，与 Python 的规则一致。Python 还补齐了拆分／合并后的诊断逃逸标记长度维护。失败记录与修复后记录都保留。

## 3. 完整 2D 实验揭示的更基础问题

场景为 64×80 网格、初始 20,480 个水与空气粒子的水柱撞水；每格 4 个粒子，20 秒、8,000 步、`dt=0.0025`，10 Hz 保存。双方使用相同种子、float32 输入、重力、尺寸与发射参数。NumPy 自行完成所有转移、压力求解和运动，不调用 C++ 求解。为了对应 graph 数组端口，NumPy 在主步边界把粒子状态往返转换为 float32。

2 秒预检发现 `dt=0.01` 的局部运动过大，因此保留该预检并改用更小步长。长序列中不启用 ST 或粒子自适应，先隔离最基本的两相及喷雾一致性。

### 默认路径不是同一个压力相场

Python `Sim._face_phase()` 由累积质量计算平方根压缩相场；Bifrost 的 `p2g_3d` 输出粒子相位的核加权平均，`step_3d` 直接由它构造 `1/rho(phi)`。这两者即使输入粒子完全相同也不同。3.2 秒共同状态中，部分面的 phi 差达到 1，753 个面的差超过 0.1。

论文 [PF-FLIP §3.3、Eq.7，印刷页 7](https://ge.in.tum.de/download/Adaptive_Phase_Field_FLIP_preprint.pdf) 明确采用累积质量的归一化、压缩和截断，并在纯相邻接处进一步消除相场波动。当前默认 Python 的 Eq.7 路径和 C++ 的标签平均路径，都不能仅凭已有单步测试就声称完整复刻这一节。Python 当前 `_face_phase()` 也没有该段所述的纯水／纯空气邻接面的额外处理。

历史 lockstep 测试把同一相场注入 Python 和 C++ 后比较压力与运动，所以能检查“给定同一个系数，求解是否一致”，却没有检查“双方是否从同一批粒子得到同一个系数”。这解释了为什么单步通过并不排除独立长序列分开。

### 保留失败的完整对照

默认相场各自运行 20 秒：

| 指标 | Python | Bifrost |
| --- | --- | --- |
| 实际出生喷雾总数 | 32,392 | 37,752 |
| 最终活跃喷雾 | 5,132 | 10,468 |
| 预算拒绝 | 0 | 0 |
| 边界拒绝 | 2,200 | 3,224 |
| 蒸发死亡 | 5,727 | 5,465 |
| 回水死亡 | 21,533 | 21,819 |

整个序列中，水粒子粗网格分布的最大总变差为 0.172，质心最大相差 2.25 格，高度 99 分位最大相差 20.96 格。这超过了预先设置的总体门槛（分别为 0.15、1 格和 4 格）。数据保持有限，但“没有 NaN”不等于通过一致性验收。

共同状态复核仍通过：分别从 0、1.8、3.2 秒的实际 Bifrost 粒子状态出发，给定相同相场时，位置最大差约 `3.8e-6` 格，速度最大差约 `1.3e-5` 格/秒，标记无差异。这把问题定位到了完整流水线定义，而不是凭画面猜测 C++ 喷雾代码出错。

### 单变量诊断，不替换默认算法

实验脚本增加了明确标注的 `--phase-law tag`：只让 NumPy 独立计算与当前 graph 一致的标签平均压力系数，其他条件不变。前 6 秒，高度 99 分位最大差从约 9.98 格降到 0.30 格；质心最大差从 0.32 格降到 0.074 格，水粒子分布总变差从 0.049 降到 0.014。

这支持相场定义差异是重要原因；它**不是**以修改参考答案的方式宣布论文验收通过。完整 20 秒诊断结果及视频另存，最终数值见随文结果 JSON。

## 此时可以做出的决定

局部发射、尺寸、飞行和被动联动可以继续作为候选实现审查。正式生产仍不能放行：先统一论文相场契约，明确纯相面处理、校准、ST 权重和自适应粒子尺度，再让相同数学定义下的 Python 与真实 graph 通过独立长序列和静水／撞击物理检查。

额外喷雾的源数仍随界面采样密度变化，原始逃逸水包如何转为液滴云也未解决；这些限制与渲染浓度不是同一问题。本轮不把云团数量加大视为参考视频效果已经可复现的证据。
