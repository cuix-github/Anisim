# 2D 后期喷雾异常：压力求解复核

2026-10-23。Xue 观察到 Bifrost 视频后半段的白色喷雾明显比 NumPy 混乱，要求检查 C++ 线性系统是否存在误差积累。本次只读取原有 20 秒诊断缓存，并从若干保存状态执行单步复核；没有重跑长序列、粗 3D、正式海浪或渲染，也没有修改或删除 40 秒生产缓存。

**当前证据不支持“压力线性系统在后半段解错或失去收敛”这个具体判断，但完整流体算法的长期稳定性仍未通过验收。** 单步残差合格不排除小误差在分类、转移和长轨迹中被放大；更不能证明当前相场对应论文。NumPy 的画面更自然也不能单独作为正确性依据。

## 从既有日志检查全部 8,000 步

读取 `plunge_20s_dt0025/bifrost/diag.*.npy`，未发现 NaN/Inf。最大迭代次数为 53，远小于本实验的 4,000 次上限。最大报告相对残差为 `9.99614e-7`，最大投影后散度为 `8.53970e-5 /s`，出现在约 3.705 秒，而不是末段持续增大。

白色喷雾出生量确实有后期增长：4–6 秒为 922 个，16–18 秒为 6,769 个，18–20 秒为 7,528 个。末段增长不能直接解释为压力残差增长。灰色空气、蓝色主体水和白色额外喷雾的 RMS 速度采用同一种粒子度量重新统计；不再把粒子 CFL 与网格 CFL 混在一起比较。

## 独立复算实际 C++ 压力方程

取保存的第 0、1280、4000、5600、7360、7960 步状态，分别约为 0.0025、3.2025、10.0025、14.0025、18.4025、19.9025 秒。对每个状态运行三个真实 Bifrost 单步：

- multigrid 预条件器，容差 `1e-6`；
- Jacobi 预条件器，相同容差；
- multigrid，容差收紧至 `1e-10`。

共同输入由独立 NumPy splat 生成，按照 fused transfer 的均值加 epsilon 形式、float32 通道端口打包，三个分支复用完全相同的文件。此测试刻意固定相场和转移输入来隔离线性求解，**不是**默认 Python 与默认 graph 整条流水线的等价证明，也没有逐步回放原 fused P2G 的每个中间数组。

C++ 新增仅在 `PFFLIP_PRESSURE_DUMP` 设置时启用的导出，保存内部双精度的面系数、右端项、压力和投影前速度。独立 NumPy 代码通过面通量重新组装 `A = -D beta G`，计算真实残差 `b-Ap`，再用普通 Jacobi PCG 求解至真实相对残差约 `1e-11`，比较消除压力常数自由度后的速度修正。没有用 float32 压力导出中的舍入噪声冒充求解误差。

| 检查 | 结果 |
| --- | --- |
| 右端项、面系数与共同输入的对应关系 | 18 个正向单步全部通过；本测试中的系数和投影前速度与独立重建完全相同。 |
| 封闭边界、常数零空间、对称性、正能量 | 通过；右端项满足 Neumann 兼容条件。随机向量对称性检查结合面通量算子的源码检查，不被当作一般形式的形式化证明。 |
| 真实残差与报告残差 | 一致；默认容差的 12 次解全部低于 `1e-6`，严格容差的 6 次解全部低于 `1e-10`。 |
| 默认 C++ 解与独立严格解的网格速度最大差 | 最大 `1.556e-5` 格/秒。 |
| 严格 C++ 解与独立严格解的网格速度最大差 | 最大 `1.436e-9` 格/秒。 |
| 离散恒等式 `div(u_new) = -dt (b-Ap)` | 通过，最大绝对偏差小于 `1e-10 /s`。 |
| 投影阶段的密度加权网格动能 | 每次投影均不增加。这不等于粒子转移、逃逸和阻力等全流程能量守恒。 |
| 独立重建速度再转换为 float32 与公开输出比较 | 每个面逐位相同。 |
| 同一状态的出生、回水、蒸发和存活数量 | 三种求解配置完全相同；本结论只覆盖这 6 个单步。 |
| 诊断导出是否改变输出 | 第 5600 步与修改前二进制保存的对照输出逐位相同。 |

第一次检查脚本把重力乘时间步误写成先做 float32 乘法；C++ 实际先把时间步提升为 double。这个检查脚本错误产生约 `5.7e-10` 的输入速度偏差，导致断言失败。已修正独立检查脚本并只重新分析现有 double dump，没有补跑这些单步。原始失败 `receipt.json` 和日志保留，正确结果为 `receipt_rechecked.json`；没有放宽门槛。

## 确认了一个收敛诊断缺口，但它没有触发本次视频异常

现有 C++ `final_residual` 来自递推残差，且在迭代次数耗尽时使用的是最后一次更新前的值。人为限制为 1 次迭代的负向对照中，报告残差为 1，真实残差约 0.0932；节点仍输出并推进粒子，投影后最大散度约 0.977/s。

独立审计正确拒绝这个负向对照。审计时这仍是待修复的防护和诊断问题；同日后续修补及前后对照见下节。不能拿来解释本视频：视频全部 8,000 步都在 53 次以内达到原设容差。最初审计没有修改收敛策略或生产求解结果。

## 比线性求解误差更明显的差异

保留同一输入速度和右端项，只把当前 graph 的标签平均相场换为独立参考的累积质量压缩相场，两边都严格求解。在 3.2–19.9 秒的 5 个状态，单步网格速度最大差为 **0.91–5.79 格/秒**，明显高于同一方程的线性求解差异。

这证明两个相场定义在这些状态下会产生不同的压力修正，不证明全部后期视觉差异已经解释清楚。相场一致的 20 秒诊断此前仍然失败；需要继续检查中间通道精度、纯相界面处理、分类和转移。

额外发射代码目前使用整个速度梯度的 Frobenius 范数，没有限定为新发生的撞击或拉伸碎裂：持续的剪切、旋转也可能满足条件。液相局部采样密度低于阈值也不自动等于发生了新的液滴碎裂。因此更多白点不等于更正确的破碎模型。

本轮还独立重建 6 个单步的发射候选、随机事件和边界拒绝，数量均与实际 C++ 一致。14 秒这一单步的 7 个出生粒子全部来自靠墙 1.5 格以内的源，但抽样不足以把整个后段异常归咎于墙面。不能从这里推出所有喷雾都在错误位置发射。部分界面候选未采到空气的情况亦保留在数值记录中，需要结合欠采样和边界逐项验证。

同日后续的 [统一相场实验](phase-contract.md) 已完成静水、6 秒撞水、容差及
时间步敏感性检查，并增加 10 个共同状态能量单步。压力投影仍不增加网格
动能，但部分状态的粒子更新与推进增加总机械能，Python 与 C++ 均复现。
局部相场对应通过不等于完整撞水通过；生产仍未放行，详细限制与后续顺序
以该记录为准。

## 后续验收顺序

先明确 PF-FLIP 相场的统一数学契约，包括质量归一化、纯相邻接面的处理、ST 权重及粒子尺度；不能为了让两段视频像而随意选择较好看的定义。再用静水和封闭撞水检查逐阶段能量、空气速度、粒子覆盖率和逃逸分类，让 Python 与真实 Bifrost 使用同一物理定义。之后做步长和求解容差的短序列收敛对照，检查小误差是否在长期被不合理放大。

发射应在基础两相流可信后单独验收：记录每个事件的位置、梯度、源速度、液滴大小和寿命，观察白色粒子究竟是在撞击处出生、在空气中被运输，还是由不应被当作界面的区域持续产生。在这些检查通过以前，不进入粗 3D 或正式重跑；也不通过减少显示白点来掩盖问题。

复现脚本为 `gates/audit_pressure_replay.py` 与 `gates/analyze_pressure_replay.py`。小型数字记录见 [pressure_replay_20261023.json](../results/pressure_replay_20261023.json)。原始输入、20 次实际 graph 调用的输出（修改前控制、18 次正向检查和 1 次负向检查）、double dump、原始失败记录、重分析记录和曲线保留在本 worktree 的 `out/runs/pressure_replay_20261023/`。

## 2026-10-23 后续：真实残差与失败状态修补

Xue 要求继续核查、明确通知重要 C++ 改动、保留修补前后对照，并证明改动
不依赖这个撞水 demo。开始修改前已告知本轮只补压力验收和失败处理，不改
0.5 相位阈值、G2P 或推进方法。基线代码为 `faeadb7`，最终验收代码为
`c74cdc5`；各臂 `job.json` 记录完整 SHA 和适用的 DLL hash。

现在旧 `step_2d`、`step_3d` 的 uniform/Jacobi/MG，以及 adaptive 主求解
和 cleanup 子求解，都在退出时用返回的压力重新计算 `b-Ap`。未满足该
求解的容差或残差非有限时，C++ 不再将这份压力用于粒子更新；返回
`iterations_used=-2`、真实残差和空状态。Python uniform、adaptive Jacobi
与 MG 对应路径也拒绝失败解。有效压力的迭代和粒子计算不变。

自适应 cleanup 使用本来就有的独立容差 `tol2`，报错显示实际采用的容差。
零迭代预算且右端项为零属于有效结果；同时修正了 adaptive 在这种情况下
把迭代数写成 -1 的诊断问题。非法 dt、容差或负迭代预算也被拒绝。

`services.logError` 只是日志，不能当作 graph 中断。因此失败分支本身清空
输出并写负诊断，`run_bifrost3` 检查每一步诊断，拒绝整段结果。即使粒子
文件按较低频率写出也不能跳过失败步。实际 iterate compound 可能继续运行
剩余迭代；本改动不是原生 graph 的即时终止机制，也不是自动回滚或重试。
直接使用节点的调用方必须处理负状态。失败时速度/散度诊断置零是无效状态
占位，不能解读为静水或散度通过。旧的有效 cache 没有被修改。

## 2026-10-23：达标候选需要复核，未达标则继续剩余预算

扩大到 112×80 的独立 transport 实验在第 206 步暴露了验收防护之后的
另一种情况：递推残差低于门槛，但真实残差为 `1.00001820149e-10`，略高于
float32 端口的 `1.00000001335e-10`。原防护正确拒绝了它，但当时还有迭代
预算，直接退出并不是唯一选择。旧失败目录和首次失败网格均保留。

先向 Xue 说明 C++ 修改，再实现：仅在递推残差声称达标时复算 `b-Ap`；
真实值达标才退出，否则用真实残差重新建立预条件方向，从当前压力继续，
不重置原始残差分母，不增加总迭代预算，也不放宽容差。最终退出仍要通过
真实残差防护。adaptive 的候选复核包含返回时的去均值步骤。正常达标路径
不改变压力迭代值。Python uniform、adaptive Jacobi/MG 与 C++ 旧 2D、
uniform 3D、adaptive 主/cleanup 共用求解函数均包含对应处理。

这是通用迭代停止处理，不依赖粒子位置、浪高、发射数量或某个 demo。

[PETSc 的真实残差说明](https://petsc.org/release//manual/ksp/)，
