# 原始 20 秒喷雾视频：差异来源与定性边界

2026-10-23。Xue 要求回到最初 NumPy／Bifrost 对照视频，先明确后半段混乱是否来自程序语言的数值问题。此前 6 秒实验关闭了逃逸和额外喷雾，且用了新的纯相面模式；它发现的 cell phi=0.5 放大机制，不能代替对原视频的调查。本轮重新使用原视频的 64×80、20 秒、8,000 步、dt≈0.0025、escape/droplet/emit model 2 全部开启的配置，保留默认 tag-mean 相场。没有修改生产 cache、渲染配置或默认物理算法。

目前可以明确区分两个问题。**原始两套实现为什么分叉：已经从全序列回放和共同状态干预定位到相场／数值边界差异、独立压力近似解、以及逃逸运动规则的离散切换。证据不支持“C++ 独有的喷雾代码错误或压力线性系统未收敛”。后半段的画面是否物理正确、怎样修成符合论文的结果：仍未验收。** 数值敏感性被定位，不等于它是可忽略的误差；也不等于找到一次局部跳变就证明它解释了所有晚期形态。

## 先复现原视频，再替换一个阶段

先以本轮开始时的 `d732c01` 代码重跑原 C++ 20 秒控制。200 个保存时刻的六个通道，以及 13 个最终状态数组，共 **1,213 个数组与原实验逐位相同**。

C++ 唯一变更是让已有 `PFFLIP_FLAT_STAGE_TRACE` 诊断也能用于 phase_model=0。显式设置该环境变量时导出每步内部 double 的投影前速度、投影后速度和相场；没有更改运算。重编译后，带导出的完整 20 秒控制再次通过上述 1,213 个数组对照。

独立的诊断 Python `LegacyPortSim` 保留原 C++ 的标签平均相场，同时匹配粒子动量的独立 float32 端口及中间平均量端口。它不是把论文参考改成新的默认答案。原本的 NumPy 参考使用不同的质量压缩相场，早期 `--phase-law tag` 也没有完整匹配这些端口；因此不能把原视频的所有差异都称作语言舍入。

随后 Python 自己完成每一步 P2G、G2P、逃逸分类、液滴半径与飞行、喷雾事件、删除和排序，**只读取 C++ 压力投影后的速度**：

- 全部 8,000 步，独立 P2G 速度及相场与 C++ trace 逐位相同。
- 全部 8,000 步的候选、事件、出生、回水、蒸发、存活数量相同。
- 200 个保存时刻的粒子位置、速度、相位、喷雾、逃逸标记和半径逐位相同。
- 真正 20 秒最终状态的位置、速度、相位、喷雾和半径逐位相同。
- 两边都累计出生 37,752 个辅助喷雾，最终存活 10,468 个。

因此原 C++ 后半段的表现能够由 Python 粒子代码原样重现。在这个完整场景内，不必假设一个额外的 C++ 喷雾、粒子推进或随机采样错误来解释差异。此实验故意共享压力阶段，是因果隔离，**不算独立求解验收通过**。

## 原路径的第一次离散分歧

另一个 Python 臂仍使用相同相场和端口语义，但独立求解压力。第一步相同输入下，投影后速度最大差为 **6.28449e-8 格/秒**。这是原视频约 1e-6 压力容差下的结果，不能与之前新相场、1e-10 容差实验的 4.19e-12 混用。

约 **2.3325 秒，第 932 步**，首次喷雾生命周期计数不同：同样出生 32 个辅助喷雾，但一个臂判定 23 个喷雾回水，另一个判定 24 个。辅助喷雾不参与网格转移，不能把这个被动粒子的删除本身当作主体流动分叉的原因。

继续越过被动喷雾差异，约 **2.4675 秒，第 986 步**出现第一个主体粒子的逃逸分类差异。粒子 14657 是水，位于约 (55.789,18.901)：

| 量 | 原 C++ 速度回放 | 独立 Python |
| --- | ---: | ---: |
| 对侧空气的局部核计数 | 2.1715259339 | 2.1710483677 |
| 两边共同的逃逸门槛 | 2.1710937130 | 2.1710937130 |
| 分类 | 逃逸液滴 | 主体水 |
| 步前位置距离 | 两者相差 0.0000191686 格 | 同左 |

原模型的条件是 `air_count > (1-esc_phi)*rho0_face`，**不是此前纯相面实验的 cell phi>=0.5**。一侧开始按抽样得到的微小液滴半径使用空气阻力和独立飞行，另一侧继续 FLIP 更新和网格速度推进。

为了排除其他输入不同的干扰，再取完全相同的原 C++ 输入粒子和投影后速度，只将这个粒子的空气计数跨过上述门槛。它从约 55.35 微米半径的液滴分支切回主体水分支；单步速度差 **1.0704434 格/秒**，位置差 **0.0175023 格**。其他粒子的速度全部不变，本步喷雾事件／生灭计数也不变。这是运动规则切换存在明显不连续的直接见证，不能作为生产修复。

这条实测链为：不同近似压力解的细小差异，逐步变成粒子位置／速度差异，跨越逃逸分类边界，再因两套运动规则不同而放大。它证明了原路径中的放大机制，但不是“一次翻转独自导致全部 20 秒差异”的证明。

## 同语言提高求解精度，没有消除后期喷雾

保持原 C++ 场景和算法，只将压力容差从约 1e-6 收紧至 1e-10，完整运行 20 秒。8,000 步最大报告真实残差从 9.99614e-7 降到 9.99943e-11，最大迭代数从 53 增至 67；因此配置确实生效。

| 完整 20 秒臂 | 累计辅助喷雾出生 | 最终存活 |
| --- | ---: | ---: |
| 原 NumPy，不同相场／中间端口 | 32,392 | 5,132 |
| 原 C++ | 37,752 | 10,468 |
| Python，共享原 C++ 投影速度 | 37,752 | 10,468 |
| Python，匹配相场和端口、独立压力 | 29,805 | 7,285 |
| 原 C++，只收紧压力容差 | 40,639 | 9,670 |

更严格的 C++ 求解改变了轨迹和出生时序，未消除后期大量喷雾；其 16–20 秒仍出生 9,664 个。独立 Python 的匹配臂也仍未通过原预设的整体分布／质心／高度对照。因此不能把“继续拧紧 tol”当作已找到的修复，也不能以较少白点判定某一条轨迹就是正确答案。

## 混乱不等于全局能量爆炸

按主粒子的数值质量统计动能加重力势能，在每 0.1 秒保存点及实际最终状态上，原 C++ 的峰值约为初始值的 1.000297，出现在首次边界夹取；20 秒末约为 **0.724432**。原 Python、匹配 Python、严格 C++ 的末值分别约为 0.673931、0.758862、0.745758。原喷雾场景的晚期没有这项指标的全局失控增长，不能将无逃逸 6 秒实验的能量超调直接移植为原视频的解释。

这不是守恒证明：被删除粒子不再计入，辅助喷雾的网格质量为零，且模型包含阻尼和其他处理。局部异常、欠采样和转移问题仍需单独判断。

原 C++ 的 18–20 秒出生 7,528 个喷雾、回水 4,652 个、蒸发 1,231 个，净存活增加 1,645 个，与存活记录严格闭合。此时每步平均有 153.6 个发射候选；实际触发事件的源平均梯度约 10.05/s，并非比早期 2–4 秒的约 15.19/s 更大。后期持续发射与合格源的数量和存活时间有关，不能仅看白点增多就推断线性系统在爆炸。

后 4 秒的 959 个请求事件中，距侧墙 1.5 格内的有 209 个，约 21.8%。所以早先少数共同状态中观察到的近墙发射，不能被扩大成“全部后期异常都来自墙”。这些是请求事件的源位置统计，不是假称所有实际出生液滴的位置统计。

## 代码和下一步边界

本轮没有修改 C++ 的压力、相场、逃逸阈值、发射或液滴飞行公式；仅扩展了显式诊断导出的适用范围。新脚本均为原场景的控制、回放、独立运行、只读分析和单步干预。原失败实验与这次失败的独立验收继续保留。

接下来应核对逃逸转换的完整数学契约：何时转入液滴模型、赋予的半径与代表质量是否一致、转换时速度是否连续、它何时参与 P2G、如何回到主体。直接给阈值加一个 epsilon 只会移动分界，不能自动消除两套运动规则间的跳跃。必须先建立符合论文的模型及通用验证，再决定修补；不以视觉降噪或人为减少喷雾代替它。

复现入口为 `experiments/trace_spray_causality.py`、`gates/trace_spray_first_branch.py`、`gates/intervene_spray_escape.py`、`experiments/analyze_spray_causality.py`。输出保留在 `out/runs/spray_causality_20261023/`，包括控制、约 2 GB 的内部场 trace、两个完整 Python 臂、严格 C++、原分支定位、共同状态干预及对照图。小型证据见 `results/original_spray_causality_20261023.json`。

首次单步干预的检查器在关闭 npz 后读取计数而报错；修正输入生命周期后另写 `escape_intervention_r2` 并通过，没有改物理或放宽检查。部分数值实验并行执行，记录的耗时不用于性能比较。
