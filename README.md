# Anisim: PF-FLIP and ST-FLIP in Bifrost

This repository implements the core of *Adaptive Phase-Field-FLIP for Very Large Scale Two-Phase Fluid Simulation* (Braun, Bender, Thuerey, SIGGRAPH 2025) inside Maya's Bifrost, using only the public Bifrost SDK and shipped nodes, and couples the result to the Gaussian-splat renderer [Aniso](https://github.com/cuix-github/Aniso): simulate a two-phase air-and-water shot in Bifrost, render the particles as Gaussians with Aniso inside a captured splat scene. The authors released only their grid data structure (MSBG, Apache-2.0), not the solver, so this is an independent implementation from the paper's equations.

## About this repository

The simulator was born inside Aniso under `sim/` and moved here on 2026-10-11 so each repository has one job: Aniso renders Gaussians, Anisim simulates. Every Aniso commit that touched the simulator came along with its author, date, and message intact (verified tree-for-tree against the originals); each carries an `Aniso-commit:` trailer naming its original hash, and references like `Aniso#38` point at the pull requests where the work was reviewed. The interface between the two repositories is the per-frame particle cache: positions, velocities, phase, escape flags, and particle scale as `.npy` arrays, produced here and consumed by the renderer.

Setup on Windows: `py -3.13 -m venv .venv` and `.venv\Scripts\pip install -r requirements.txt` (versions pinned to the ones every recorded result was produced with), then `nodes\build.bat` to build the custom Bifrost nodes (Visual Studio 2022 and Bifrost 3.1 for Maya 2027). Gates run from their own folder, for example `cd gates` then `..\.venv\Scripts\python.exe validate_p2g.py`. Every validator exits nonzero on failure.

## Why this paper, in three sentences

PF-FLIP fills air with FLIP particles too, so wind, splashes, spray, and air entrainment come from physics instead of "white-water" heuristics. Its phase field costs nothing: it is the splatted particle mass, normalized, so there is no level set and no surface reconstruction anywhere. The only genuinely new machinery over textbook FLIP is a variable-coefficient pressure solve, where each cell face is weighted by the mass that landed on it.

## Architecture decisions (settled)

- **Uniform-grid pressure solve, adaptive particles.** The paper's grid adaptivity (its Sections 4 and 6) exists to reach ocean scale; a room-scale shot does not need it, and the particle side (Section 5, including the per-size FLIP-blend correction of 5.3) is where the cost explosion actually is, because air fills the whole domain with particles. Escalation paths if footage ever demands more: higher uniform resolution, then static nested refinement, then a standalone build on the authors' Apache-2.0 MSBG. Consequence accepted: domain size is capped by the uniform solve; a snug box around the action.
- **One custom C++ node, everything else stock.** The two-phase pressure projection does not exist in the product (the shipped liquid and gas projections each assume a single density) and is our one SDK node. Verified stock wheels for the rest: `splat_points_into_volume` (arbitrary properties, linear or quadratic kernel, exposes accumulated weights, which *is* the phase field's raw material), `sample_property` for grid-to-particle, `transport_particles`, standard field math, and the public iteration machinery the shipped solvers themselves are built from.
- **Public surface only.** Shipped files, public SDK, public docs. The custom node reads and writes plain arrays attached as custom properties, deliberately independent of Bifrost's internal volume layout.
- **Reference first.** A small pure-Python 2D implementation of the core loop (`reference2d/`) is the executable spec; every Bifrost stage is validated against it and against the paper's own test cases.

These were settled at the start; two were later reversed by measurement, and the milestone log below records both: P2G moved into a custom node (milestone 6.75, after profiling showed the stock splat layer was 94 percent of the cost), and the adaptive pressure solve came back as a staged milestone (6.5a) once the pressure solve became the largest remaining slice.

## What is in this repository

One folder per job. Run outputs from every script land in the ignored `out/` at the root.

- `reference2d/`: the executable spec, the pure-Python 2D implementation every Bifrost stage is validated against, with its validation scenes, `VALIDATION.md`, and figures in `reference2d/results/`.
- `nodes/`: the custom Bifrost SDK operator pack (`PFFlipSpike`, named for the feasibility spike it grew from), built with `nodes\build.bat` (needs Visual Studio 2022 and Bifrost 3.1 installed with Maya 2027). It started as the variable-coefficient projection with a built-in 1D two-phase hydrostatic test; `PFFlipSolve.{h,cpp}` is the milestone-5 step node, `PFFlipSolve3.cpp` the 3D step with its multigrid solve, `PFFlipP2G.cpp` the fused transfer layer.
- `graphs/`: the Bifrost graphs and the `.bat` launchers that run them headlessly through bifcmd. `hydro_test.json` (`run_hydro_test.bat`) is the spike's test. `phase_field_probe.json` (`run_phase_field_probe.bat`) is the milestone-4 graph, stock nodes only: particles in from .npy, phase splatted into a volume with `splat_points_into_volume`, phi sampled at probe positions and written back as .npy; its `view_volume` output carries the volume with fog density set to phi. `solve_step_test.json` and `solve_step3_test.json` wrap the step nodes for lockstep tests. `sim_2d.json`, `sim_3d.json`, `sim_3d_fused.json` and `p2g_test.json` are generated by `generate_sim_graph.py`: the full simulation loops and the fused-P2G wrapper. `loop3d.py` is the 3D loop runner the loop gates and the 3D experiments share: it seeds the particle state (or resumes one from a full-state dump), saves it as .npy and runs `run_sim_3d.bat` or `run_sim_3d_fused.bat`.
- `gates/`: the validation ladder, every check that says the Bifrost side still agrees with the spec and with physics: `validate_*.py`, `verify_engineering.py`, and `compare_phase_field.py` (the milestone-4 comparison against the 2D reference); `validate_resume.py` checks that a run resumed from its full-state dump reproduces the uninterrupted run bit for bit. Each exits nonzero on failure.
- `experiments/`: benchmarks, demos and studies: `demo3d.py` (which re-exports `run_bifrost3`, the 3D loop runner the loop gates share; it lives in `graphs/loop3d.py`, beside the `run_sim_3d*.bat` launchers it drives), `run_bore_suite.py`, `bench_p2g_finale.py`, `demo_p2g_speed.py`, `demo_splash.py`, `threading_experiment.py` and `render_threading_demo.py`.
- `maya/`: the phase field made playable in Maya. `phase_field_play.json` is the phase-field graph with a frame port, `export_play_sequence.py` dumps the reference 2D dam break as a numbered .npy sequence, `build_maya_play_scene.py` wires a scene where Maya's timeline drives the graph, and `play_in_maya.bat` does all of it in one click: press play in the viewport and the fog you see is the phase field of the validated two-phase simulation, frame by frame. `pfflip_graphs_config.json` exposes both phase-field compounds to Maya (point `BIFROST_LIB_CONFIG_FILES` at it).
- `results/`: committed evidence per campaign, videos, charts and receipts: `results/bore_suite/` for the milestone-6 overnight suite's verdicts, `results/p2g/` for the fused transfer layer, `results/threading/` for the threading record.

Spike results (2026-09-30): the projection returns a 1000:1 density-contrast column to rest at the 1e-6 level and reproduces the analytic hydrostatic pressure jump; unpreconditioned conjugate gradient needs 211 iterations at 64 cells and 1843 at 256, which is the measured argument for adding a preconditioner in 3D.

## Milestones, each with its "done when"

1. **Spike landed.** This folder builds and the hydrostatic test passes on a clean checkout. Done when `run_hydro_test.bat` reports max velocity after projection below 1e-4.
2. **2D reference validates the core loop.** Hydrostatic rest, a two-phase dam break, and a Rayleigh-Taylor instability, the last being a two-phase-only phenomenon no single-phase solver can produce. Done when RT fingers develop from a seeded perturbation and the dam break front advances plausibly, with images in the repository.
3. **Validation gate: the paper's claims tested comparatively.** Done 2026-09-30, passed: see `reference2d/VALIDATION.md` (single-phase FLIP baseline vs two-phase on a sealed trapped-air pocket; interface transport vs a grid scalar; the viscosity law calibrated; mixing measured). One carried instruction: recalibrate the blend-to-viscosity constant per implementation.
4. **Bifrost graph produces the phase field with stock nodes.** Done 2026-09-30: `phase_field_probe.json` reads the same jittered two-block slab the 2D reference seeds (identical particles via .npy), splats phase with the stock node, and the fields agree, mean |difference| 0.002, maximum 0.08 confined to the one-voxel interface band, interface midpoint within 0.03 voxels. Figure: `reference2d/results/validation/phase_field_bifrost.png`. Authoring facts that cost debugging time (see also: every file write inside an iterate must feed the success accumulator or lazy evaluation prunes it, learned twice; the shipped libraries contain equality but no greater/less comparisons; empty float3 arrays do not round-trip through the NumPy file nodes): a new point property needs `set_geo_property` (the `_data` variant only overwrites existing ones); `splat_points_into_volume` writes only into existing tiles, so build the volume from the points first with `points_to_volume`, and it needs fog density on or the volume has no voxels at all; give the splat one property name per node, a two-name filter string misbehaved.
5. **The custom node does the projection inside the graph loop.** Done 2026-10-05, validated in three layers. Lockstep: `PFFlip::Solve::step_2d` (the projection grown from the spike, plus the per-phase FLIP transfer and RK2 advection, mirroring the reference line by line) run on identical inputs matches python with the same CG iteration count and face velocities to 1e-6 (`validate_step.py`). Full loop: `sim_2d.json` runs the whole simulation inside one headless graph, an iterate whose state is the particle arrays, with the staggered channels assembled by stock splats via the shifted-points MAC trick; the dam-break front stays within 1.9 cells of the reference over the full run and post-projection divergence stays at solver tolerance (`validate_loop.py`). Physics anchors, no reference in the loop: hydrostatic column stays at rest, the sealed air cushion holds its 10.6-cell gap exactly as the gate measured, and 19:1 Rayleigh-Taylor grows textbook mushrooms. Sheets and curves in `reference2d/results/validation/bifrost_*.png`. Known honesty note: fixed substepping is at its limit. The dam break peaks at CFL 0.54; the splash demo (`demo_splash.py`, the violent three-way plunge sheet in `bifrost_splash_demo.png`) measures air-jet speeds up to 505 cells per second as the trapped film squirts out at impact, CFL 5 at that instant, with 137 of 560 substeps above 1. The rows still match the reference, which shares the same treatment at the same dt, but the lesson is PF-FLIP-specific and now measured: the fastest thing in a violent two-phase scene is the air, a phase free-surface solvers don't even carry, so milestone 6 requires CFL-adaptive substepping rather than treating it as polish.
6. **3D at small scale**, the complete uniform-grid picture: adaptive particles (coarsen far-field air, per-size blend correction), a multigrid-preconditioned solve (measured need: 200-500 Jacobi-PCG iterations in 2D), CFL-adaptive substepping (measured need: 505-cells-per-second air jets in the splash demo), and escaped-particle droplets and bubbles, pulled forward because the showcase scene demands them. Done when a 3D dam break in a box runs at around 128³ overnight or better and conserves volume reasonably, and a 3D plunge showcase shows crown splash, rising bubbles, and foam. Phase-1 progress 2026-10-06: `step_3d` landed with a geometric multigrid V-cycle inside flexible PCG. Validated three ways: at nz=1 it reproduces the 2D method in exact lockstep (533 iterations, both implementations); multigrid solves the same dam-break system in 9 iterations instead of 533 with the same solution to 1e-6; and a real 32x32x8 two-phase column returns to rest at 1e-7 with the analytic pressure jump within 4 percent. Progress through 2026-10-08, each phase its own gated PR (Aniso PRs #26 through #35): escaped-particle droplets and bubbles; ST-FLIP (the authors' SIGGRAPH 2026 follow-up, adopted into the substepping slot after its own 2D gate, with velocity-adaptive jitter attenuation and output-time resynchronization) in the node and through the loop graph; deterministic threading (whose first speed claim a controlled benchmark retracted - the loop is graph-side dominated); adaptive particles (reference, node, and loop graph: ~51 percent of particles saved with represented volume conserved exactly, tiers combined through an epsilon-inversion weight recovery that keeps everything on stock splats); and solid AABB obstacles, lockstep-exact. **Finish line met 2026-10-08** by the overnight wet-bed bore suite (`experiments/run_bore_suite.py`; verdicts in `results/bore_suite/summary.json`), judged against Stoker's analytic bore speed: the trusted configuration (80x32x40, small dt) runs the bore at 1.059x Stoker in 86 minutes; ST at 8x dt reproduces it (1.063x) at an eighth of the cost; production (ST plus adaptive particles) is 16.6x cheaper than trusted with 22 percent particle compression, at 0.916x; and the 256x64x128 finale in production configuration, 16.8M seeded particles, matches Stoker to 1.7 percent (0.983x) with zero obstacle penetrations in 107 minutes. The adaptive configuration agrees with theory better at production resolution than at the comparison resolution (0.983 against 0.916), so the low-resolution slowdown is a resolution effect. The night caught two bugs: the bore front must be measured on elevated liquid, because the wet bed spans the flume from t=0, and time-resynchronized display positions ignored obstacles, drawing spray inside the pillars (fixed for good in Aniso PR #43). The suite ran as a chain of launches resumed from full-state dumps, because the background runner kills tasks near the one-hour mark. That suite code and this record were pushed after Aniso PR #35 merged, so they never reached main; they landed on 2026-10-11, with the resume made bit-exact on the way (`gates/validate_resume.py`: the ST jitter is seeded from the step index, so a resumed run now continues the stream through `step_offset` instead of replaying it).
6.5. **The adaptive-solve spike pair**, deliberately after 6 because its multigrid machinery is most of the work already done. Two separate claims, two gates: (a) the solver math in 2D, junction stencils, conservative transfer, convergence on an irregular hierarchy, validated as a numpy adaptive reference against the uniform reference on the gate scenes, then the node in lockstep; (b) the Bifrost foundation, a small probe that stores the adaptive grid in a native multi-depth volume and walks it through the preview-tier traversal API behind a one-file adapter. Honest expectation: little speedup at snug-box scale; the value is proof that the declared limitation is removable, and our own measured evidence for what the source reading said. 3D extension only if a shot demands it. **Spike 1, the profiling that gates the pair, done 2026-10-09** (`PFFLIP_PROFILE=1` prints per-phase node times; two finale-scale runs of 4 and 12 substeps resumed from the mid-bore overnight state, walls differenced so startup cancels): at 256x64x128 with 6.8M particles a production substep costs 96.4 s of wall, of which the entire custom node is 5.6 s and the multigrid-PCG pressure solve 0.9 s at 23 iterations — 0.9 percent of the substep, 16 percent of the node. Amdahl therefore caps a *perfect* adaptive pressure solve at about one percent of wall-clock. The bill lives in the graph layer (around 91 s per substep: the stock splat families over the particle arrays, plus the per-substep NumPy dumps), and even inside the node the particle pass at 4.5 s outweighs the solve five to one. Verdict: gate (a) remains available as solver craft, but neither gate buys milestone 7 anything measurable; if the hero scene needs speed, the measured target is the splat layer and the dump policy, not the solve. **Stage 1 of gate (a) PASSED 2026-10-10** (`reference2d/adaptive_solve.py`, gated by `reference2d/validate_adaptive_solve.py`): finite volume on a graded 2:1 quadtree, junction stencils built variationally (A = G^T beta G, symmetric PSD by construction) with offset-corrected lateral interpolation exact for linear fields in every graded configuration, and the adjoint-consistent right-hand side b = G^T(A u*). Five checks: refined-everywhere reduces to the 5-point operator at 1.8e-15; the uniform solve matches `pfflip2d.project` itself at 1.7e-14 on a real dam state; measured convergence order 1.99/2.02 ACROSS junctions (the naive 1.5-distance stencil scored 0.90 before the variational rebuild); the 1000:1 hydrostatic column rests at 1e-4 of the gravity kick on an adaptive grid; and on a real dam-break state the drift-vs-band-width curve gives the criterion its validated operating point - fine band >= 5 cells around the interface, 50 percent of unknowns saved, water-face drift at 6e-4 of max speed (the beta ratio protects liquid exactly as predicted), with the known 2-cell air edge-skin reported and shrinking monotonically with band width. Three lessons for stage 3, each measured the hard way: junction samples must be laterally aligned (the naive stencil's first-order error is exactly dt g/3 in hydrostatics); the divergence must be the operator's own adjoint (mixing conventions cost 6 percent hydro residuals from an operator whose consistency error was 4e-4); and the refinement criterion must respect the 1000:1 density tail and the band-noise skin, not just distance to the interface. **Stage 2 PASSED 2026-10-11** (`Multigrid` in the same module): a geometric V-cycle over the collapsed-quadtree hierarchy - every level is a stage-1 Operator assembled by the same variational rules, residuals sum into parents, corrections inject into children, production smoother constants - inside flexible PCG. On the stage-1 systems at the same 1e-9 tolerance: dam band-5 323 -> 20 iterations, 1000:1 hydro 180 -> 21, solutions identical to 2e-10, five levels. The adaptive hierarchy converges like the uniform multigrid precedent (533 -> 9); what remains for stage 3 is the 3D node and its receipts.
6.75. **The fused transfer layer**, 2026-10-09, one day after the spike-1 profile (Aniso PR #37) put a price on the stock-splat convenience and flipped the stock-first posture for the one data path that dominated the bill. P2G moved from thirty stock `splat_points_into_volume` plus thirty `sample_volume` invocations per substep into one custom node, `PFFlip::Solve::p2g_3d`, which scatters every channel - mass, per-axis momentum, phase, the ST temporal weight - onto all three face grids and both size tiers in a single pass, straight into the flat arrays the step node consumes. The kernel is now the reference's Eq. 6 on the reference's face frames, so the pipeline moved *closer* to the paper, not further: the dam-break gate's historical 1.9-cell front gap against the reference - stock-kernel mismatch all along - halved to 1.0 cell and the centroid drift fell from 1.24 to 0.35 cells, with hydro-column grid divergence at 2.6e-7 (unit gate `validate_p2g.py`: reference operator at float rounding, independent 3D numpy at 2.4e-4, axis permutation bit-exact; system gate `validate_p2g_loop.py`). Receipts, resumed from the same mid-bore finale state as the spike with the stock baseline re-reproduced within 3 percent the same day: 96.4 s per substep to 10.22 s, **9.4x** at 256x64x128 with 6.8M particles (`bench_p2g_finale.py`), and 8.8x on the 20-second production bore-with-pillars demo whose side-by-side video with live compute clocks lives in `results/p2g/` (`demo_p2g_speed.py`). `step_3d` untouched, channel semantics drop-in, every prior gate standing; the eps-inversion trick now reconstructs sums the fused node computed exactly, earmarked for retirement at the next cleanup. The scatter is serial and deterministic; threading it is a measured decision for later, not a reflex. **The exact pie, measured 2026-10-10** (`dump_gate` + P2GPROF landed with it; the full receipts are in the Aniso PR #40 description): a fused finale substep is 10.3 s = particle pass 4.6 + scatter 3.0 + pressure solve 2.3 + assemble/correct 0.2 + graph residual 0.3, and the per-substep dumps cost no measurable time — the `dump_every` port's value is disk, not clock. The solve is 2.3 s here, not spike 1's 0.9 s, for an understood reason: the reference's r = 1 kernel draws a sharper interface than the radius-1.5 stock splat, and the harsher beta contrast takes 33-55 MG-PCG iterations where stock needed 13-15 — fidelity bought at solver expense. Net position: the solve already carries 22 percent of the substep, the neighborhood the ST-FLIP authors' own Table 1 reports (26 percent, on 32 threaded cores with their adaptive multigrid on), so the pipeline already has the paper's cost shape. Agreed order from here: deterministic threading of the scatter and the particle pass (the two big slices; per-core our stage costs are within about 2x of the authors', so the missing factor is literally their 32 threads), then milestone 6.5a with its production case in hand. A further gated lever: the authors solve pressure to 1e-4 where we run 1e-6.
**Threading follow-through, 2026-10-10.** Destination-owned slabs now parallelize the fused P2G and the two particle-count scatters while retaining original particle addition order at every face. Independent particle work is threaded; the original RNG stream and merge/split order stay intact. Fresh same-day finale measurements are 8.26-8.44 s per substep before versus 4.44-4.62 s after at 32 workers, about 1.8x overall. The new measured pressure share is roughly 54 percent, so this configuration is the baseline for milestone 6.5a. Identity checks at 1/8/32 workers and a larger parallel flat case preserve every saved array exactly. The 20.04-second 3D bore also matches all 1,146 saved arrays, with zero represented-volume drift and zero actual-state solid penetrations. Nine existing regression scripts pass; the legacy stock-graph ST bubble-count gate fails identically on unchanged main and on the threaded build, with all 502 saved outputs identical. The bore audit separately catches display positions entering pillars in both builds. Both gaps remain open, not silently reclassified as passing.

**Both gaps closed, 2026-10-11, by instrumented forensics rather than tolerance edits.** The display-position gap was the missing resync clamp (Aniso PR #43). The count gate's story took a history trajectory (peaks at eight main commits: the python side never moved, the graph side dropped exactly at Aniso PR #35), four wedge experiments that acquitted every piece of the tier machinery, and a final one-wire revert to pin it: Aniso PR #35 made particle mass loop state fed by the node's temporally weighted out_mass - REQUIRED for adaptive merging, and the correct ST normalization (the reference weights mass and momentum together; the pre-#35 graph weighted only momentum). The old "passing" 76/106 was that inconsistency partially cancelling a second defect: the validator forwarded only rho0_face while the graph's escape-parameter defaults are all zero, so the two sides had run different escape physics since the test was born (its bubble ratio sat at 0.41 against a 0.4 bar from day one). With parameters matched, the corrected solver scores its best agreement ever: droplets 99 vs 94, bubbles 237 vs 259 - seed ensembles on both sides confirm the old gap was systematic and the new agreement is not luck. validate_escape's loop check was the same disease in a different organ: its hand-rolled bifcmd invocation predated the #35 graph and never supplied the phase state, which initialized empty and read every particle as air; routed through run_bifrost3 it returns exactly to its birth band (91 vs 102 droplets, 153 vs 140 bubbles). And the reason all of this hid for five days: ten of twelve validators printed FAIL while exiting zero - every one now carries a real exit code. The experiment, phase breakdown, receipts, labeled comparison video and validation details are in [the threading record](results/threading/README.md).

The production path remains uniform solve plus adaptive particles in a snug box. Position updated again 2026-10-09 by milestone 6.5's spike 1: the profiled pressure share at finale scale is 0.9 percent of wall, so the adaptive solve is officially craft, not production path. Position updated a third time 2026-10-10, after the fused transfer layer (milestone 6.75) shrank the denominator and its sharper kernel raised the solve's own cost: the solve now carries 22 percent of a fused substep — the same share the authors' own per-stage table reports — so milestone 6.5a is back to being a production proposition, sequenced after deterministic threading.
